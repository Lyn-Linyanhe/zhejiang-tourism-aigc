## 关键冲突解决口径

1. **知识库**：以 PR #3 为准（181 实体 / 544 条 `fact_records`，全部带来源记录；`scripts/verify_kb_quotes.py` 联网核验 535/535 通过）。PR #1 的 11 城覆盖强断言（`assertCountEqual`）保留。
2. **knowledge.py 服务层**：以 PR #3 实现为基底（`canonical_city` / `get_entity` / `resolve_entity` / `english_query`），PR #1 仍被调用的 `normalize_city` / `topic_entities` / `source_record` / `shot_references` 用 PR #3 原语重建追加，两套调用方共用一个匹配实现。
3. **TaskInput 字段顺序**：以 PR #3 为准（音量字段在前，保住既有位置参数契约）；PR #2 的 `subject_lock` / `subject_reference_path` 移至末尾（`from_dict` 与前端均按关键字传参，不受影响）。校验合并了主体长度限制与「5–180 秒、2–12 镜、每镜 ≥3 秒」范围校验。
4. **Pexels 素材**：保留 PR #2 的视频优先实现（自包含 `PexelsAssetProvider`，`video-first/video-only/photo-only` 三模式），PR #3 的 `provenance` 元数据并入视频与图片两条返回路径；PR #1 的 `StockProvider` 引擎（`stock` / `pixabay` 来源）共存。
5. **音频**：逐段保持 48 kHz 单声道（PR #3 响度口径；`silenceremove` 在立体声输入上裁不干净，实测裁剪 1.65s vs 正确 1.10s），立体声在拼接层统一生成（PR #1 的 48 kHz 双声道成片口径保留在 voice.wav）。默认 ducking 采纳 PR #3 的「不压低（推荐）」。
6. **素材提交与复用**：`append_asset` 按 `shot_id` 替换（PR #3，防旧素材残留）；复用判断保留 PR #1 的 `selection_key` 口径并叠加 PR #3 的发布模式直取素材库。
7. **前端**：PR #1 表单布局与台账 UI 组（创作参数档案 / 逐镜核验 / 费用对账）+ PR #2 视觉验收面板 + PR #3 输入自由度与素材库浏览，作品档案页同时保留回收站与指标总览。
8. **API**：PR #1 的 `ledger` / `visual-review` / `cost` 与 PR #3 的 `metrics` / `export` / `billing` / `publication-observations` / `library/assets` / 曲库 GET 共存；任务详情同时携带 `metrics`（PR #3 口径）与 `cost.billing`（PR #1 对账口径）。
