**一个必须注意的坑**：模型倾向把数字写成中文（"二零零八年""四十一人""五千三百年"），最初的自动比对只认阿拉伯数字，把 5 条全判成"无支撑"。修正方式是先把中文数字转写再比对，这才得到真实结果 5/5。这类假阴性很容易让人误判模型在编造。

## 过程中修掉的三个问题

**1. 系统环境变量盖住了 `.env`**

`config.py` 的加载逻辑是"环境变量已存在就不覆盖"，而机器上残留一个旧的 `LLM_API_KEY`，导致服务一直用旧 key 请求新网关，报 401。解决方式是启动服务时显式传 `LLM_API_KEY` 覆盖。

**2. `.env` 里 LLM 配置重复**

第 5 行和第 16 行各有一组 `LLM_BASE_URL`，去重时保留了旧值。已清理并统一指向网关。

**3. 音乐库缺失阻断生成**

第一次跑 API 任务时脚本已生成成功，但卡在"没有匹配 舒缓+国风 的授权音乐"。这是本地曲库覆盖不足，不是脚本链路问题。用 `music_mood=无音乐` 绕过，任务正常完成。

## 还没做的

2. **画面—旁白匹配是粗判**：逐镜表里 `visual_narration_match` 只判断画面描述是否含旁白主体词，不是真看图。严格验收需要生成画面后人工比对。
3. **页面编辑没实测**：API 层导出验证通过，但浏览器里的编辑、保存、再导出没点过一遍。
