# 浙江全省小红书 MCP 采集（2026-11-22）

## 结论

这一轮把小红书采集从“绍兴 6 景点试点”扩到 **全省 11 个市、38 个点位**：**323 条笔记（详情完整 323 条）、322 张图片、132 条镜头意图**。

深度只压在三座已有知识库的城市（杭州 5 点位、宁波 3 点位、绍兴 6 点位），其余 8 市各 1 个标志性点位、每处 5 条，做“地标 + 1–2 个画面点”的浅覆盖。这样全省每个市都有可用画面线索，但没有把采集成本摊平。

所有数据仍是 `reference-only`：笔记文字与图片版权归原作者，**不得作为事实来源、成片素材或发布素材**。

## 图片采集的两次修正

第一版按“点赞最高的 2 条笔记、各取前 3 张”下载，结果 116 张里有一批不能看：

- 温州、嘉兴、湖州、舟山的头图是**路线图、攻略封面、合影牌**；
- 金华横店前两条高赞是**明星应援和游戏联动**，4 张全是海报。

第二版改了三处：

1. 跳过推广类笔记（应援、联动、抽奖、探店、福利等关键词）；
2. 攻略类笔记跳过封面，从第 2 张开始取实拍图；
3. 浅覆盖城市从 2 条笔记 × 2 张提到 3 条 × 3 张。

补采后又对舟山、金华、嘉兴、温州、湖州做了定向二次取图。二次扩量后，16 个新点位改由浏览器路径取图（`scripts/xhs_fetch_images_browser.py`），最终 **322 张、38 个点位全覆盖、0 失败**。

## 镜头意图怎么用

- `confidence=high` 的 50 条可直接进脚本分镜备选；`medium` 34 条做备选或需再看图；`low` 1 条（鲁迅故里水野栀子）只有单篇笔记支撑。
- `angle_type=shot` 是画面镜头，`narrative` 是预期管理（人流、票价、动线提醒），后者不该写成画面。
- `claim_risk` 记录了该角度涉及的待核说法（票价、开放年代、取景地、“最/唯一”类表述）。**这些一律不进 `fact_records`**，要写事实必须回景区官网、政府/文旅公告或正式名录。
- `contact_sheet` 指向对应的接触表，可以直接看图判断构图，不必打开原笔记。

## 许可与合规

- 只使用 `search_feeds` 与 `get_feed_detail` 两个只读接口；**没有调用发布、点赞、评论、收藏、私信**。
- 图片下载仅用于内部目视判断与构图标注，存 `runtime/` 且已加入 `.gitignore`；**没有提交仓库、没有进素材库、没有进入成片**。
- `docs/` 下的 CSV 已剔除 `xsec_token`（会话敏感，会过期）；带 token 的完整版只留在 `runtime/_xhs_collect_multi/notes_with_tokens.csv`，同样不入库。
- 需要正式图片时：取得作者书面授权，或换 Wikimedia Commons / Pexels / 官方授权图 / 团队自摄。

## 两条采集路径与速度对比

当天先走 MCP，触发限流后改用浏览器，两条路都保留：

| 指标 | MCP（`xhs_mcp_client.py`） | 浏览器直读（`xhs_browser_collect.py`） |
|---|---|---|
| 搜索一次 | 2–4s | 8.2s |
| 单条详情 | 0.5–1s | 8.6s（轮询，无固定等待） |
| 10 条点位（串行） | 约 15s | 约 90s |
| 10 条点位（3 标签页并行） | 不支持 | **约 30s** |
| 账号级限流 | 连续约 100 次后 100% 失败 | 未触发（走真实页面导航） |
| 分享数 | 有 | 恒为 0（详情页不返回） |
| 其他字段 | 齐全 | 齐全，另有 IP 属地与每张图尺寸 |

结论：

- **MCP 健康时更快**，适合小批量、有节制的采集；但它是账号级共享配额，三实例并行只会更快耗尽。
- **浏览器路径更抗压**，且支持多标签页并行——实测 3 条并行耗时 8.2s，与单条 8.6s 几乎相同，瓶颈是网络往返而非条数。
- 并行上限建议 3–5 个标签页；再多会拖慢每个页面，也会对目标站点造成不必要的压力。
- 两条路不要同时对同一账号施压，今天的限流很可能就是三路 MCP 并行叠加触发的。

## 局限

1. 8 个浅覆盖市已扩到 3 个点位，但仍只覆盖每市最具代表性的 3 处，不能代表该市全貌。
2. 点赞未归一化，搜索排序有热度与商业推广偏差；横店这种“活动/明星”内容尤其容易挤占结果。
3. 浅覆盖城市的多为“多景点攻略”，目标点位常只是其中一站，已用 `spot_mentioned` 标记。
4. 图片只取每条笔记的前几张，**没有逐张看完整图集**；构图判断基于接触表 + 标题/摘要母题。
5. 未做跨平台对照（官方号、B 站、Trip.com），也未联系作者授权。
6. 非遗类实体（黄酒、越剧、莲花落、乌篷船制作、香榧、宁波 9 项）没有画面材料；乌篷船笔记拍的是“坐船”不是“造船”，不能混用。
7. 浏览器路径不返回分享数，且依赖人工登录态，无法无人值守长期运行。

## 复现方式

### 路径 A：MCP（快，但受账号级限流约束）

```text
# 1) 启动只读 MCP 实例，确认登录
python -I scripts/xhs_mcp_client.py --port 18060 search --keyword 西湖 --limit 1

# 2) 逐点位采集（每点位之间停 1-2 分钟；不要 3 路同时施压同一账号）
python -I scripts/xhs_mcp_client.py --port 18060 collect --spot 西湖 --keyword "杭州西湖 景区" \
    --out runtime/_xhs_collect_multi/xihu.json --details 10 --limit 20
```

### 路径 B：应用内浏览器直读（抗限流，支持并行）

前提：应用内浏览器已登录小红书。由 `scripts/xhs_browser_collect.py` 提供页面内取数片段，
在浏览器工具里按下面的顺序调用：

1. `tab.goto("https://www.xiaohongshu.com/search_result?keyword=<关键词>")`；
2. `tab.playwright.evaluate(SEARCH_JS)` 取候选，按 `likes` 降序截取前 N；
3. 准备 3 个标签页，用 `Promise.all` 同时 `goto` 三条笔记页；
4. 每条用 `READY_JS` 轮询（150ms 一次，最多 30 次），数据就绪即读，**不要固定 sleep**；
5. 结果按点位写入 `runtime/_xhs_collect_multi/<slug>.json`，字段与 MCP 分片一致。

### 公共后处理

```text
# 聚合去重 + 质量标记（incomplete_spots 会列出详情失败率 >30% 的点位）
python -I scripts/xhs_aggregate_notes.py

# 下载图片 + 生成接触表
python -I scripts/xhs_fetch_images.py
python -I scripts/xhs_fetch_extra.py   # 定向补图

# 生成镜头意图表（会校验笔记 ID、实体 ID、tag 词表）
python -I scripts/xhs_build_shot_map.py
```
