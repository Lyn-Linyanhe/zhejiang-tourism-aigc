## 任务清单

### 1. 运镜（静图变活）

`_render_shot()` L56-58 现在的 filter 链只有 `scale/crop/format`——一张死图循环 5 秒，**画面完全静止**。六个镜头拼起来观感就是六张图轮播。

要加 `zoompan`：

```python
f"scale={w*2}:{h*2}:force_original_aspect_ratio=increase,"
f"crop={w*2}:{h*2},"
f"zoompan=z='min(zoom+0.0008,1.15)':d={frames}:s={w}x{h}:fps={fps},"
f"format=yuv420p"
```

> ⚠️ **必须先放大到 2 倍再处理，否则会有明显抖动。** 这是 `zoompan` 最常见的坑。

**注意**：视频素材不需要运镜（它本身就在动）。按 `shot["asset_media_type"]` 分流。

### 2. 统一调色

也是 L56-58 那条 filter 链——现在**没有任何色彩处理**。六个镜头冷暖和影调会明显跳。

加一条：

```python
"eq=saturation=1.06:contrast=1.04:brightness=0.01,"
"curves=preset=medium_contrast,"
"colorbalance=rm=0.01:bm=0.02"
```

调色参数从 `RenderRequest.grade` 读（P2 的 `consistency.py` 产出），为空时用内置默认值。

### 3. 转场（兑现声明过的能力）

`render()` L180-196 现在用 `concat` demuxer——**硬拼接，零转场**。

而 `models.py:119` 早就声明了 `transition: str = "fade"`，代码里从未使用。**这是「声明的能力与实现不符」，评委翻代码就能发现，比单纯没做更被动。**

契约里定义了五个必须实现的转场：

```
TRANSITIONS = ("fade", "dissolve", "slideleft", "slideright", "zoom")
```

### 4. ⚠️ 时长归一化（最危险的一处改动）

`xfade` 会让前后镜头**重叠**，总时长会变短：

> 你们现在严格是 6×5 = **30.000 秒**。直接换 xfade 会变成 29.5 秒左右——**打破你们最引以为傲的确定性指标**。

两条路：
- **A（推荐）**：保持每段 5 秒，用段内**淡入淡出**（`fade` filter，不重叠）。视觉有柔和感，总时长不变。
- **B**：用 `xfade`，但同步调整分镜时长分配和四道校验，让最终仍归一化到 30.000 秒。

**方案 A 更稳、改动更小。** 选 A 的话转场列表要相应简化。

### 5. 字幕按真实时间戳

`media.py:290-305` 的 `create_srt()` 现在按镜头**名义时长均分**。

改成吃 P3 的 `cues`（真实音频时间位置）。这样字幕才能和配音钉死，不会渐进错位。

### 6. 音画 mux

`_mux_audio()` L101-147 现在接的是原始音频。要接 P3 的 ducking 产物。

> ⚠️ P3 想改 L118-123 的混音 filter 链，但那是你的文件。**接口对齐后由你落地。**

### 每次改完都要验的四条

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 final.mp4
# 期望 30.000000 —— 转场不许把总长改掉

ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate -of csv=p=0 final.mp4
# 期望 720,1280,25/1

ffprobe -v error -show_entries stream=codec_type -of csv=p=0 final.mp4
# 期望同时有 video 和 audio
```

## 交付方式

本项目**不使用远程仓库**。各自完工后，把成果打包发回给负责人合并。

**只发你名下的文件 + 你的 AI 日志**，打包成一个文件夹：

```
P4-交付-<日期>/
├── backend/app/services/renderer.py
├── backend/app/providers/media_ffmpeg.py

├── P4-AI-LOG.md
└── 说明.md
```

### 两条硬要求

1. **只发自己名下的文件。** 如果你改了别人的文件，说明越界了——发回来会被退回。
   （没有版本控制，负责人只能靠文件清单判断你有没有越界。）
2. **必须发 AI 日志。** 日志是负责人唯一能知道「你改了什么、为什么这么改、
   AI 哪里写错了、你有没有真的验证过」的来源。没日志的交付不予合并。

### 说明.md 里写三件事

- **新增的环境变量**（负责人要同步进 `.env` 和 `.env.example`）
- **新增的依赖**（负责人要同步进 `requirements.txt`）
- **你验证时跑了什么命令、结果如何**

### 负责人那边的合并方式

你不需要会 git。负责人本地有仓库，会：

```bash
git diff --stat          # 先看你改了哪些文件
git diff <文件>          # 再具体看改了什么
git add -A && git commit # 确认没问题才提交
```

所以**别改别人的文件**——一改就会在 diff 里显形。
