## 任务清单

### 1. Provider Registry（拆硬编码）

现在有两处写死的分支链，加任何新 provider 都要动核心代码：

| 位置 | 现状 |
|---|---|
| `orchestrator.py:336-342` | `if asset_source == "pexels" ... else OfflineAssetProvider()` |
| `orchestrator.py:441-505` | TTS 四级嵌套 try-except（upload → OpenAI-TTS → edge-tts → Windows SAPI） |

改成 `registry.py` 查表。**关键设计**：支持 `contract.FallbackChain` 声明降级顺序，这样 P2 的画面回退策略只是注册表里的一条配置，不用来改你的文件。

```python
FallbackChain(slot="asset", providers=["cloud-i2v", "cloud-t2i", "local-library", "offline"])
```

最后一个必须是永远可用的本地兜底（`OfflineAssetProvider`，`media.py:30-86`）。断网/限流/欠费时自动往下走一格，往 trace 里记 `fallback_used=true` 和原因。

### 2. 阶段重排（v1 契约的核心变更）

```
旧：scripting → storyboard → assets → audio → rendering
新：scripting → storyboard → audio → assets → rendering
```

改 `orchestrator.py:194-224` 的 `_run()`。

**为什么**：画面是云 API 按秒计费的。旧顺序下配音后发现语速不对，分镜时长一变，已生成的视频全部作废。

配套要重写 `_normalize_shots()`（L282-307）——它现在强制「分镜时长之和 == `input.duration`」，引入配音真实时长后会打架。新逻辑：**以 P3 的 cues 为准反推每个镜头的真实时长**。

### 4. HTTP API

### 两条硬要求

1. **只发自己名下的文件。** 如果你改了别人的文件，说明越界了——发回来会被退回。
   （没有版本控制，负责人只能靠文件清单判断你有没有越界。）
2. **必须发 AI 日志。** 日志是负责人唯一能知道「你改了什么、为什么这么改、

- **新增的环境变量**（负责人要同步进 `.env` 和 `.env.example`）
- **新增的依赖**（负责人要同步进 `requirements.txt`）
- **你验证时跑了什么命令、结果如何**

### 负责人那边的合并方式

