## 任务清单

### 1. 云文生图 `image.py`

参考实现：`MoneyPrinterTurbo/app/services/material.py:1406` `generate_images_openai()`

**必须暴露 seed 和负向词。** 不暴露的话画面可控性无从谈起，一致性就没法做——这是你后面能做出「六个镜头像一部片子」的前提。

顺带一提：那个函数的注释写着它可以指向本地 ComfyUI/SD 网关，API key 允许为空。**留着这个口子**，将来若要切本地推理不用改代码。

### 2. 云图生视频 `video.py`

参考实现：`MoneyPrinterTurbo/app/services/volcengine_seedance.py`

关键改动在 L233 的 payload：

```python
# 现在（纯文生视频）
"content": [{"type": "text", "text": term}]

# 要改成支持追加图片项（图生视频）
"content": [
    {"type": "text", "text": term},
    {"type": "image_url", "image_url": {"url": ...}},
]
```

> ⚠️ **字段名请对着火山方舟最新官方文档确认，不要凭记忆写。** 我看到的适配器里没有这部分。

**必须沿用的逻辑**（MPT 写得很好，直接抄）：
- 提交接口不做自动重试——超时或 5xx 可能发生在付费任务已创建之后，盲目重试会造成重复扣费
- 轮询间隔、超时上限、失败状态分类
- 下载校验（远端成功了但没下下来，要能区分）

**已确认的接口参数**（从适配器读出，可直接用）：

| 项 | 值 |
|---|---|
| 模型 | `doubao-seedance-1-0-pro-250528` |
| 单次时长 | 2–12 秒 |
| 分辨率 | 480p / 720p / 1080p |
| 比例 | 支持 9:16 竖屏 |
| 单次超时 | 1800 秒 |

### 3. 一致性策略 `consistency.py`

这是你**唯一需要反复试**的模块，也是最出效果的：

- **固定 seed 策略**——同一任务的 6 个镜头怎么分配 seed？固定同一个？还是基点+序号？
- **统一 prompt 前缀 / 负向词**——保证「宋韵」「水墨」这类风格词在 6 个镜头里一致
- **统一调色参数**——输出一个 `grade` 字典，交给 P1 透传给 P4 去做 FFmpeg 调色

产出直接进 `RenderRequest.grade`。

### 4. 成本台账 `cost.py`

汇总每次 provider 调用上报的 `cost`。归你是因为**最贵的调用是你自己的**，你最懂计费口径。

每个 provider 返回的 `AssetResult.cost` 就是数据源（契约里已定义）。

## 你的输入 / 输出

**输入**：`shot["visual_prompt"]` + `style_ctx`（知识库颜色等）
**输出**：`contract.AssetResult`

**三条硬性要求**（`AssetResult.validate()` 会检查）：

| 要求 | 原因 |
|---|---|
| `seed` 必须回填 | 不回填就无法复现，一致性无从谈起 |
| 图生视频必须回填 `first_frame_path` | 「这一镜为什么长这样」的唯一证据，也是失败重试的起点 |
| `media_type` 必须准确 | 渲染器据此决定用静图运镜还是视频铺时长 |

**好消息**：`path` 不管是图还是视频，都能直接进现有渲染管线——`renderer.py:47-48` 已经按扩展名分流了。

## 交付方式

本项目**不使用远程仓库**。各自完工后，把成果打包发回给负责人合并。

**只发你名下的文件 + 你的 AI 日志**，打包成一个文件夹：

```
P2-交付-<日期>/
├── backend/app/providers/image.py
├── backend/app/providers/video.py
├── backend/app/services/consistency.py

├── P2-AI-LOG.md
└── 说明.md
```

### 两条硬要求

1. **只发自己名下的文件。** 如果你改了别人的文件，说明越界了——发回来会被退回。
   （没有版本控制，负责人只能靠文件清单判断你有没有越界。）
2. **必须发 AI 日志。** 日志是负责人唯一能知道「你改了什么、为什么这么改、
   AI 哪里写错了、你有没有真的验证过」的来源。没日志的交付不予合并。

### 说明.md 里写三件事

- **新增的环境变量**（负责人要同步进 `.env` 和 `.env.example`）
- **新增的依赖**（负责人要同步进 `requirements.txt`）
- **你验证时跑了什么命令、结果如何**

### 负责人那边的合并方式

你不需要会 git。负责人本地有仓库，会：

```bash
git diff --stat          # 先看你改了哪些文件
git diff <文件>          # 再具体看改了什么
git add -A && git commit # 确认没问题才提交
```

所以**别改别人的文件**——一改就会在 diff 里显形。
