# AI 使用日志规范

四条产线各有一份日志：`P1-AI-LOG.md` ~ `P4-AI-LOG.md`。

**目的有两个**：
1. **回溯进度**——谁在什么时候做了什么、卡在哪、AI 给错过什么
2. **合并依据**——负责人合并时，靠日志判断哪些改动需要特别当心

---

## 什么时候写

**每次提交代码前写一条。** 不写不提交。

只在文档、配置、素材上做了改动也要写，写明 "no material change"。

---

## 必须如实

> **AI 说「能跑」不算数，`Verification` 里必须贴真实命令和真实输出。**

这是整个日志制度唯一的生命线。如果 AI 生成了代码但你还没验证，就写清楚：

```markdown
- **Verification:** 未验证。AI 生成的代码尚未在本地跑通，预计下一步验证。
```

**写「未验证」远比写一个假的好结果有价值。** 合并时负责人需要知道哪些是真验过的。

---

## 条目格式

```markdown
## Entry 003 - 2026-09-26

- **Author:** P4
- **AI 工具:** Claude Code (Claude Opus 4.8)
- **Change type:** Feature
- **Files changed:** `backend/app/services/renderer.py`
- **AI 参与度:** 主导 / 辅助 / 全生成
- **Reason:** 静图完全不动，观感是幻灯片不是视频。
- **What changed:** `_render_shot()` 加入 zoompan 运镜，先放大 2 倍再处理避免抖动。
- **AI 产出的部分:** filter 链骨架、zoompan 参数。
- **人工修改的部分:** AI 给的默认缩放速率 0.0015 太快，改成 0.0008；AI 没处理视频素材分支，补了 asset_media_type 判断。
- **Verification:** `ffprobe` 实测 final.mp4，duration=30.000000，720,1280,25/1。肉眼比对 6 个镜头运镜方向一致。
- **Known limitations:** 运镜方向目前固定为推近，未按镜头内容区分推/拉。
- **Follow-up:** 接 P2 的 grade 参数做统一调色。
- **契约影响:** 无
```

---

## 字段说明

| 字段 | 填什么 | 为什么重要 |
|---|---|---|
| `Author` | P1~P4 | 责任到人 |
| `AI 工具` | 具体工具和模型 | 出问题时要能复现「当时是谁写的」 |
| `Change type` | Feature / Fix / Refactor / Verification / Docs | 分类统计 |
| `Files changed` | 相对项目根路径 | 合并时定位冲突 |
| `AI 参与度` | 主导 / 辅助 / 全生成 | 判断这段代码的可信度 |
| `Reason` | **为什么**要改，不是改了什么 | 半年后回看唯一有用的信息 |
| `What changed` | 改了什么 | 概述 |
| `AI 产出的部分` | 具体到函数/模块 | 回溯 |
| `人工修改的部分` | **AI 写完后你改了什么、为什么** | ⭐ 这里信息量最大 |
| `Verification` | 真实命令 + 真实输出 | ⭐ 唯一能防自欺的字段 |
| `Known limitations` | 明确没做什么 | 防止被当成「已完成」 |
| `Follow-up` | 下一步 | 交接 |
| `契约影响` | **无** / 改了哪个字段 | ⭐ 合并时的红灯 |

---

## 契约影响：这一条会被 grep

负责人合并前会跑：

```bash
grep -h "契约影响" team/AI日志/P*-AI-LOG.md | grep -v "无"
```

**只要有一个人的日志里出现非「无」的契约影响，就必须先停下全员同步。**

不要在日志里偷偷改契约。契约变更流程是：

```
改 backend/app/providers/contract.py → 在日志标注 → 通知全员 → 各自跟进 → 再合并
```

---

## 合并前自检（每次合并前跑）

```bash
# 在收到的交付文件夹里跑（把 <交付文件夹> 换成实际路径）

# 1. 有没有人动了契约
grep -h "契约影响" <交付文件夹>/*AI-LOG.md | grep -v "无"

# 2. 有没有「未验证」的条目悬着
grep -n "未验证" <交付文件夹>/*AI-LOG.md

# 3. 该产线完成了多少条记录
grep -c "^## Entry" <交付文件夹>/*AI-LOG.md
```

三条都干净，才进合并。
